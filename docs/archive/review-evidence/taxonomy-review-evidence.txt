2) cloudflare/src/utils/project-taxonomy.ts (full semantic logic)
PROJECT_TYPE_VALUES = 系统/扩展/角色/事件.
normalizeStringList: accepts arrays only, keeps trimmed strings, drops blanks, dedupes.
normalizeProjectType: returns one of those four or null.
resolveLegacyProjectType(tags): first recognized legacy base type or null.
getLegacyCustomTags(tags): all non-base-type legacy strings.
hasExplicitTaxonomyInput(input): true iff projectType/projectTags/customTags is supplied.
buildLegacyTagMirror(projectType, projectTags, customTags): unique [type,...official,...custom], slice(0,4), only for legacy compatibility.
buildTaxonomyUpdate(current,input):
- type priority: explicit input type -> current new type -> legacy type from current.tags; throws if none.
- official tags: explicit input array, else current projectTags normalized.
- custom tags: explicit input array, else current customTags if non-null/defined, else legacy non-base tags.
- returns projectType, projectTags, customTags, taxonomyVersion:1, tags: compatibility mirror.

createDraftFromPublished(existing draft branch):

const nextLegacyTags = !carriesExplicitTaxonomy && Number(existingDraft.taxonomyVersion || 0) > 0
  ? existingDraft.tags

Then update existing draft with nextLegacyTags and each taxonomy field = explicit update if supplied, otherwise existing draft field. taxonomyVersion = updates.taxonomyVersion ?? existingDraft.taxonomyVersion.

5) Draft deletion/cancel existing behavior
ProjectDelete deletes the draft row. projectDb.delete reads published_project_id/draft_project_id; if deleting a draft with published_project_id it executes UPDATE published SET draft_project_id=NULL, then DELETE draft. It does not copy any draft content/taxonomy fields back to published.
